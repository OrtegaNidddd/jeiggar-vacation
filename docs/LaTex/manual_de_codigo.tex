\section*{Introducción}
\addcontentsline{toc}{section}{Introducción}
% =================================================

El presente manual de código documenta la estructura técnica, arquitectura, dependencias, convenciones de programación y principales flujos de desarrollo de la plataforma web \textbf{Jeiggar Vacation}. El documento está dirigido a desarrolladores, administradores técnicos y futuros integrantes del proyecto que necesiten comprender, mantener o ampliar el sistema.

La plataforma fue desarrollada como una aplicación web moderna orientada a la gestión y promoción de destinos turísticos nacionales e internacionales. Su implementación combina tecnologías de frontend, servicios en la nube, autenticación, almacenamiento y base de datos mediante Supabase, React, TypeScript, Vite y Tailwind CSS.

Este manual permite conocer la organización interna del proyecto, la función de sus módulos principales, las reglas de codificación aplicadas y los procedimientos necesarios para instalar, ejecutar y modificar el sistema de manera controlada.

\section{Visión General}
% =================================================

Esta sección presenta una descripción general del sistema, sus áreas principales y el flujo general de información entre los usuarios, la interfaz web y los servicios conectados.

Permite a los usuarios explorar destinos nacionales e internacionales, cotizar planes por WhatsApp y acceder a información de servicios complementarios como asistencia médica, transporte, conectividad y trámites.

\section{Guía de Configuración}
% =================================================

Esta sección explica los requisitos y pasos necesarios para instalar, configurar y ejecutar el proyecto en un entorno local de desarrollo.

\subsection{Prerrequisitos}

Antes de ejecutar el sistema, el equipo debe contar con las siguientes herramientas instaladas:

\begin{itemize}
    \item \textbf{Node.js} versión 20 o superior.
    \item \textbf{npm} versión 10 o superior.
    \item Cuenta activa en Supabase con un proyecto configurado.
\end{itemize}

\subsection{Instalación paso a paso}

Los siguientes comandos permiten clonar el proyecto, instalar dependencias, configurar variables de entorno y ejecutar el servidor local.

\Needspace{12\baselineskip}
\begin{lstlisting}[language=bash]
# 1. Clonar el repositorio
git clone <url-del-repo>
cd jeiggar-vacation

# 2. Instalar dependencias
npm install

# 3. Configurar variables de entorno
cp .env.example .env.local

# 4. Ejecutar servidor de desarrollo
npm run dev
\end{lstlisting}

El servidor se ejecutará normalmente en la dirección \code{http://localhost:5173}.

\subsection{Variables de entorno}

Las variables de entorno permiten conectar el frontend con el proyecto creado en Supabase.

\Needspace{7\baselineskip}
\begin{lstlisting}[language={}]
VITE_SUPABASE_URL=https://xxxxxxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxxxxxx
\end{lstlisting}

El archivo \code{.env.local} no debe subirse al repositorio, ya que contiene datos de configuración propios del entorno local. Para compartir la estructura esperada de variables, se utiliza el archivo \code{.env.example}.

La seguridad de acceso a los datos se gestiona estrictamente mediante políticas de (Row Level Security) configuradas de forma nativa en Supabase.

\section{Documentación de Lógica Principal}

Esta sección documenta los archivos y procesos principales del sistema. Su objetivo es explicar cómo se conectan los servicios, cómo se procesan los datos y cómo se maneja la lógica de autenticación y administración.

\subsection{\texorpdfstring{Cliente Supabase: \code{src/lib/supabase.ts}}{Cliente Supabase: src/lib/supabase.ts}}

Este archivo centraliza la creación del cliente de Supabase. La aplicación debe importar siempre esta instancia para evitar configuraciones duplicadas.

\Needspace{5\baselineskip}

\end{lstlisting}

La regla principal es no crear nuevas instancias de \code{createClient} en otros archivos. Todas las conexiones deben realizarse importando \code{supabase} desde \code{@/lib/supabase}.

Este helper convierte las rutas de imágenes almacenadas en la base de datos en URLs públicas completas de Supabase Storage.

\subsection{Servicio de destinos públicos}

Ubicación: \code{src/features/destinations/services/destinations.service.ts}

Este servicio centraliza las consultas de lectura utilizadas por la web pública. No modifica datos, solamente obtiene información de destinos, países y ciudades.

\subsubsection*{Flujo de datos}

\diagramfigurehere
{diagramas/flujo-servicio-destinos-publicos.png}
{Flujo de datos del servicio de destinos públicos}
{Funcionamiento de la interfaz pública al solicitar información de destinos, consulta a Supabase y retorno normalizado de los datos al frontend.}
{fig:flujo-servicio-destinos}

\subsubsection*{Funciones disponibles}

\textbf{\code{fetchDestinationBySlug(slug: string)}}
\begin{itemize}
    \item Carga un destino completo por medio de su identificador URL.
    \item Relaciona la información con ciudades o países según el tipo de destino.
    \item Retorna \code{null} cuando el destino no existe.
    \item Solo devuelve destinos activos.
\end{itemize}

\textbf{\code{fetchFeaturedDestinations()}}
\begin{itemize}
    \item Obtiene destinos marcados como destacados.
    \item Ordena los resultados según \code{sort\_order\_home}.
    \item Se utiliza en la página principal.
\end{itemize}

\textbf{\code{fetchInternationalDestinations()}}
\begin{itemize}
    \item Obtiene destinos de tipo internacional.
    \item Relaciona los destinos con su país correspondiente.
    \item Ordena los resultados alfabéticamente.
\end{itemize}

\subsubsection*{Generación automática de slug}

El slug se genera a partir del nombre del destino. Este valor se utiliza para construir rutas amigables dentro de la aplicación.

\Needspace{15\baselineskip}
\begin{lstlisting}[language=typescript]
function generateSlug(name: string) {
  return name
    .toLowerCase()
    .normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '')
    .replace(/[^a-z0-9\s-]/g, '')
    .trim()
    .replace(/\s+/g, '-')
    .replace(/-+/g, '-')
}
\end{lstlisting}

Ejemplo: \code{Cañón del Chicamocha} se convierte en \code{canon-del-chicamocha}.

\subsection{Modificar un campo en la capa de datos}

Cuando se añade o modifica un campo desde la consola de Supabase, se debe actualizar el frontend para evitar errores de compilación o desincronización de tipos.

\begin{enumerate}
    \item Ejecutar la modificación en Supabase mediante SQL Editor.
    \item Actualizar el tipo correspondiente en \code{src/domain/types/}.
    \item Actualizar la consulta estructurada en el servicio correspondiente.
    \item Actualizar el mapeo relacional de nombres si aplica.
    \item Actualizar el formulario administrativo si el campo debe ser editable por el usuario.
\end{enumerate}
